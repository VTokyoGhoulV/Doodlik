# Doodlik

Личная 2D-игра на Unity для Windows и Android. Котик Дудлик поднимается по платформам, собирает монеты и бонусы, проходит испытания и открывает новые образы. В экспериментальном режиме экспедиций к прыжкам добавляются находки, бой и выбор между возвращением с добычей и продолжением пути.

**Статус:** активная разработка. Версия в настройках проекта — `0.0.4`; исходники включают тестовое обновление экспедиций.

## Возможности

- Автоматические прыжки, движение влево и вправо, переход через боковые границы экрана.
- Генерация платформ с учётом достижимости прыжка; движущиеся и разрушающиеся платформы, кустики с пчёлами и усиленным отскоком.
- Несколько уровней сложности, смена природных зон по высоте, опасности и временные усиления.
- Монеты, гардероб, косметические награды, испытания и достижения.
- Рекорды, статистика попыток и локальное сохранение прогресса.
- Точное управление и управление с инерцией; клавиатура на ПК и касания на телефоне.
- Книжный и альбомный форматы на Android, меню, настройки музыки и эффектов.

### Экспедиции

Тестовый режим с отдельным игровым циклом:

1. Собрать находки в ограниченный рюкзак; одну находку можно защитить от потери.
2. Сражаться с грозовыми жуками, атакуя прыжком сверху, и подбирать редкие материалы.
3. На привале вернуться с грузом или выбрать временный талант и продолжить подъём.
4. Потратить принесённые материалы в мастерской, а монеты — на постоянные улучшения.

Временные таланты действуют в пределах попытки. Постоянная прокачка сохраняется между экспедициями. Боссы пока не реализованы.

## Запуск из исходников

Понадобятся Git с Git LFS, Unity Hub и редактор **Unity 6000.5.2f1**. Версии зависимостей находятся в `Packages/manifest.json` и `Packages/packages-lock.json`.

```powershell
git lfs install
git clone https://github.com/VTokyoGhoulV/Doodlik.git
cd Doodlik
git lfs pull
```

1. Добавьте папку `Doodlik` в Unity Hub и откройте указанной версией редактора.
2. Дождитесь импорта ресурсов и восстановления пакетов.
3. Откройте сцену `Assets/Scenes/SampleScene.unity`.
4. Нажмите Play, выберите режим в главном меню и начните игру.

Для проверки мобильного интерфейса выберите Android как активную платформу в Build Profiles. Режимы экрана и управления выбираются в настройках игры. На ПК используется альбомный формат.

## Сборки

Для Android установите через Unity Hub модуль Android Build Support с SDK, NDK и OpenJDK. Минимальная версия Android в настройках — API 26 (Android 8.0).

Обычную сборку можно создать через **File → Build Profiles**: выберите Windows или Android и убедитесь, что включена сцена `Assets/Scenes/SampleScene.unity`. Для первого знакомства удобнее выбрать отдельную пустую папку вывода.

В проекте также есть команды меню:

- `Doodlik → Build Windows` — сборка Windows.
- `Doodlik → Build Both To Desktop` — обычные сборки Windows и Android.
- `Doodlik → Build Android Test APK` — Android-сборка для проверки.

Эти команды записывают результат в папку `Doodlik/v<версия>` на рабочем столе и могут обновить существующие файлы этой версии. Специальный `ExpeditionTestBuild` предназначен для отдельной тестовой копии проекта; правила описаны в [руководстве тестовой версии](Docs/ExpeditionTest-20261102-Readme.txt).

В Git хранятся исходники и ресурсы. Исполняемые файлы, APK, кэши Unity и журналы сборки исключены из репозитория.

## Структура проекта

```text
Assets/
├── Player.cs, Spawner.cs          # управление и генерация платформ
├── GameplayPreferences.cs        # режим, сложность и управление
├── Run*.cs                       # попытки, бонусы, статистика и рекорды
├── PlayerProgress.cs             # монеты, покупки и сохранения
├── Challenge*.cs                 # испытания и достижения
├── Expedition*.cs                # экспедиции, добыча, враги и мастерская
├── FrontEndUI.cs, GameMenuUI.cs   # экраны и меню
├── Resources/                    # настройки, графика и шейдеры
├── Scenes/SampleScene.unity      # основная сцена
└── Editor/                       # сборка и редакторские проверки
Packages/                         # зависимости Unity
ProjectSettings/                  # настройки проекта
Docs/                             # правила, история обновлений и проверки
Tools/                            # проверки вне Unity
```

Игровые системы используют компоненты MonoBehaviour и отдельные классы для настроек, прогресса и состояния попытки. Интерфейс во многом создаётся при запуске. Сохранения локальные: PlayerPrefs и сериализованные JSON-данные с версиями и резервными копиями.

## Проверки

Основные проверки генерации, игрового цикла, прогресса, интерфейса и экспедиций находятся в `Assets/Editor/*Validation.cs`. Это собственные инструменты проекта; наличие пакета Unity Test Framework не означает, что все эти проверки запускаются обычной кнопкой Run All.

Проверку расписания бонусов можно выполнить без запуска Unity, используя PowerShell 7:

```powershell
pwsh -File Tools/ValidatePickupSchedule.ps1
```

При подготовке репозитория 11 ноября 2026 года:

- эта проверка прошла для 256 последовательностей по 3000 платформ;
- проверены соответствие прямых зависимостей manifest/lock, наличие `.meta` у ресурсов и отсутствие повторяющихся GUID;
- все 195 C#-файлов, включая поставляемые примеры, сверены со снимком проекта, использованным для тестовых сборок от 2 ноября: содержимое совпадает;
- новый запуск Unity, новая сборка и проверка на физическом Android-устройстве не выполнялись.

Описание ранее выполненных сценариев находится в [заметках о развитии игры](Docs/JourneyUpdate.md), [проверке сложности](Docs/Difficulty-QA-20261014.txt) и [правилах обновления экспедиций](Docs/ExpeditionRoguelite-Minimum.txt).

## Разработка с ИИ

Проект развивается с существенным участием ИИ-ассистента Codex: он используется для написания и переработки C#-кода, подготовки проверок и сборок, а также работы над интерфейсом.

Автор определяет игровую идею, формулирует требования к механикам, выбирает направление развития и оценивает результаты итераций. Такое разделение работы является частью истории проекта.

## Ограничения

- Игра находится в разработке; баланс и интерфейс экспедиций ещё меняются.
- Сохранения находятся на устройстве; облачная синхронизация и сетевая игра не реализованы.
- Часть редакторских проверок и специальных сборочных команд рассчитана на изолированную копию в `.utmp`, чтобы не затрагивать обычный прогресс и сборки.
- `Tools/ValidateReleaseBindings.py` при проверке существующих Windows/Android-сборок не разрешает ссылку на встроенный ресурс `unity default resources`, лежащий в подпапке `Resources`. Инструмент останавливается с ошибкой; его результат нельзя считать полной проверкой сборки. Ресурс в проверенных файлах присутствует.
- Проверки в редакторе и чтение файлов сборки не заменяют игровое тестирование на физических устройствах. Производительность на слабых телефонах отдельно не подтверждена.
